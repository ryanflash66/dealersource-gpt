# Decisions

The shared task spec is authoritative. It is referenced by URL in README, not copied here. No sibling solution code or logs were read.

1. **Runtime and package manager:** Node.js 24 native TypeScript stripping plus npm and Node's test runner. No third-party runtime or test dependencies. `npm test`, `npm run pipeline -- --offline` and `npm run dashboard:dev` work without an install or network.
2. **YAML syntax:** configuration uses JSON-compatible YAML 1.2. This keeps the three `.yaml` files valid and editable while removing an install-time parser dependency. The loader intentionally accepts this subset, not arbitrary YAML syntax.
3. **Zero-credential storage:** the default is an atomic local JSON database with an exclusive run lock and resumable tables. Supabase Postgres/PostGIS RPC storage is selected only when deployment variables are present. The local adapter is explicitly not represented as tested hosted Postgres.
4. **Supabase state model:** core tables retain full typed records as JSONB payloads, with indexed identifiers, dedicated PostGIS parcel geometry, RLS, a durable state snapshot and a lease/revision checked commit RPC. The dashboard reads an authenticated RPC directly and cannot obtain raw message or service-role secrets.
5. **Published shared dashboard:** adopted the template at parent commit `8ed035502569f9a921aa9b1175a92cc106ee493a` as soon as the final milestone check found it published. `dashboard.css` is byte-identical; `tokens.css` changes only `--accent` to `#10A37F`, with all derived and semantic tokens untouched. Four dynamic views use the shared shell, cards, chips, evidence tables, score segments, cases, banners, config layout and map preview classes. Additional report metadata stays under `ui`. The small integration stylesheet makes the exported absolute footer participate in document flow, prevents overlap on variable-length real reports, and handles missing/long dynamic data. Offline mode uses system-font fallback, the shared icon sprite and static map preview, never network fonts or tiles. Upstream CSS comments retain their original punctuation to honor the byte-preservation requirement.
6. **Offline mapping:** an accessible synthetic coordinate map with an equivalent ranked list renders without external assets. The deployed path supports self-hosted MapLibre and PMTiles modules/styles. Public OSM tiles and public Nominatim are never scheduled defaults. Bundling unrequested map libraries or downloading map extracts was not necessary for offline acceptance.
7. **Drive-time membership:** OSRM route time at each candidate is the default membership test for the 60-minute driving catchment, not a straight-line radius. ORS/Valhalla adapters also exist. A provider that cannot return sufficient travel evidence leaves the site non-viable.
8. **Evidence:** unknown, invalid, future-dated or expired gating evidence never passes. Official zoning needs written authority or a layer plus exact use-table citation. Conditional use passes only when verified. Flood area ties fail because exactly half outside is not a majority. Shaded X warns. Premises checks are additional exclusions for the already-held dealer license, not a licensing workflow.
9. **Money and shared sites:** both $600 and $1,000 are hard inclusive bounds. Decimal quote parsing avoids numeric coercion. Shared lots sort after every standalone site regardless of score. An enclosed office and display capacity matter more than acreage.
10. **Identity:** canonical address plus exact suite/display scope is the site identity. Syndicated offers merge without confidence inflation; a second suite remains a separate candidate even at the same parcel.
11. **Original fixtures:** all example properties, parcel IDs, contacts and written replies are synthetic. The demo fixture clock is September 16, 2026 for reproducible dashboard rendering. Fixture validity is evaluated at that fixture clock; live views evaluate current evidence expiry. No fixture is presented as a discovered real property.
12. **Sources and permission:** unknown robots status is blocked as well as disallowed robots. Unclear terms require explicit reviewed configuration. LoopNet, Craigslist and Meta collection are excluded by the cited terms; Reddit commercial access and Crexi/local-site permission remain unclear and disabled. Source classes are seeded, not a claim of complete inventory coverage. Discovered broker POIs become disabled review candidates, not automatically authorized crawl targets.
13. **Model contract:** scheduled Claude uses an explicit JSON request/response file with bounded extraction/classification tasks. Unknown outputs remain pending and make the run visibly incomplete. Optional Claude API use requires selection, paid enablement and deployment credentials. No Max token extraction, subscription-to-API assumption or silent paid fallback.
14. **Outreach:** only approved question templates, published leasing/official contacts, and the configured mailbox may be used. No new-lead daily cap is introduced. Per-recipient/site cooldown is five days by default, followed by at most two follow-ups. No offers, negotiation, signatures, payments, phone/SMS or non-email channel is implemented. Required formal applications remain escalated rather than bypassed.
15. **Mail failure semantics:** an intent is persisted before send. Ambiguous outcomes and interrupted dispatches are escalated, not blindly retried. Fixture sends are recorded without network. Replies are ingested before and after dispatch, and exact-sender stop requests suppress contact. OAuth refresh is supported; quota errors and bounce thresholds pause sending.
16. **Official-source geometry:** the offline path uses original recorded centroid/area facts. A conservative convex-overlay implementation handles simple live polygons; complex or incomplete geometry stays unverified. The supplied PostGIS flood function unions/intersects arbitrary official geometries. Parcel/road attribute names and official layer endpoints are deployment configuration, not guessed guarantees.
17. **Provider exceptions:** the task table's official-only/no-paid layers are exceptions to its general free-plus-paid statement. Optional paid adapters are implemented but disabled by default. Where vendor schemas vary, the adapter accepts a documented `dealersource` normalized envelope; unsupported or incomplete native responses remain unknown rather than fabricated.
18. **No live configuration during build:** all real credentials and addresses are deployment-only environment variables. `.env.example` has empty values and purpose comments. No account connection, cloud project, Vercel deployment, live model call, real Gmail send, public crawler run or paid provider was activated.
19. **Validation scope:** offline unit/integration/replay and dashboard-build acceptance are executable. A local Postgres/PostGIS smoke test is supplied separately. The build environment has no Docker, psql or local browser binary, so no actual database-engine or browser-visual pass is claimed from static migration/HTML tests.
20. **Git isolation:** all implementation changes and commits are in this child repository only. Shared system/task prompt texts were not copied; the explicitly authorized dashboard assets were copied as required. Peer solutions and peer logs were not consulted. The parent submodule pin is left for the PM to update after evaluating the child commit.
21. **Score defaults:** configured weights are traffic 0.40, visibility 0.25, distance 0.15, rent 0.12 and competitors 0.08. Traffic normalizes at 40,000 AADT, frontage at 100 meters; visibility combines frontage, corner and line-of-sight evidence. Missing context receives no fabricated favorable value. This is a transparent comparison heuristic, not a sales forecast.
22. **Publication transport:** the terminal has no GitHub credential helper. After all checks pass, use the already-authorized GitHub integration to publish the small local commits in order, retain their original local commit IDs in commit messages, verify identical Git trees, and preserve the original local history before aligning the working branch. Do not request or extract new credentials.
23. **Concurrent remote updates:** remote `main` acquired a different implementation while this isolated local build was in progress. Do not overwrite or force-push it. Publish this independently authored working tree on `gpt/offline-complete-20260916`; keep `main` untouched. Only path/commit metadata was inspected to detect divergence, not that implementation's source content. Remote-only files inherited by the new branch were removed from that branch before publishing this solution, so the branch does not mix implementations. The original remote history remains on `main`; original local commits are retained locally as well.
